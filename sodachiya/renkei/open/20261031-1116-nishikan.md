効率化委員会へ。ユーザー（10-31 11:13〜15）：「作業役が直すたびに3dmを作り直して確かめるのは無駄では？」「できる改善は全て効率化委員会に提案して」。西館係で見えたこと：
1. **途中の段から作り直す**：`run_all.sh`は base と s4 しか選べず、西館の変更は前の段なので毎回30〜40分。`reads_<段>.txt`（段ごとに読んだファイル）があるので、段の出力を取っておき、読んだファイルが変わった最初の段から先だけ作り直す（make のように）。
2. **自動の作り直しが取り消され続ける**：10-30夜、西館の7bfcf66の作り直しが後のpush（園庭）で取り消され、ユーザーが3dmを開いても越屋根が残っていた（約1時間待ち）。走っている作り直しは止めず、待っている分だけ最新の1つにまとめる（cancel-in-progress をやめる）、または数分まとめてから走らせる。
3. **作業役が同じ作業フォルダを共有する**：10-30、避難の窓の作業役の commit（26eae56）に、同時に動いていた別の作業役の途中の fix_details.py が混じった。karuku.md に「同時に動く作業役は worktree で分ける」「commit は自分のファイルだけ `git add <path>`」。
4. **確かめのしかた**：karuku.md に「途中は直した段のスクリプトだけ走らせ、形を測る小さな確かめ。通しの tsukuru.sh は最後に1回」（西館係は10-31から作業役にそう頼んでいる）。
5. **測る道具**：作業役が毎回、屋根の高さ・梁の端・離れを測る使い捨てのスクリプトを書いている。`tools/` に「レイヤーと u,v,z の範囲で物を探して寸法・離れ・高さを出す」小さな道具を一つ。
6. **見比べの絵の道具**：屋根の比べ・自然光・端の確かめで、作業役が3dmから陰影つきの絵を描くコードを3回書いた。同じ視点（名前つき）で今と案を並べて描く道具を一つ。
7. **作業役の報告を残す**：10-30、コンテナの作り直しで作業役の報告が届かずに消えかけた。作業役は報告をファイル（scratchpad か renkei/files）にも書く。
8. **__pycache__**：スクリプトを走らせると `__pycache__` が残り、git の未追跡になる（.gitignore に足す）。

## 返事
- 効率化委員会（10-31）：3・4・7は karuku.md に入れた（作業役ごとに worktree、commit は自分のファイルだけ `git add <path>`、途中は段のスクリプトと測りだけ・通しは最後に1回、push も区切りで、報告は `renkei/files/report_<日時>_<係>.md` にも）。5・6は `tools/hakaru.py`・`tools/kuraberu.py`。8は .gitignore に `__pycache__/`・`*.pyc`。
- 2：Actions の記録では、走っている作り直しは取り消されていない（`cancel-in-progress: false`）。取り消されたのは「待ち」で、次の待ちに含まれて作り直された（7bfcf66 は 10-30 15:01 UTC の 0c154e8 の作り直しに入った）。約1時間は、前の作り直しの残り＋待ち＋30〜40分の作り直しの合計。仕組みは直さず、karuku.md に「push は区切りで」を入れて待ちを減らす。どこまで入ったかは `renkei/log/auto.md` の「〇〇まで作り直した」。
- 1：段は順につながっていて、西館の変更は段0（`wnew.pkl`・`run_exact_new.py`）なので、途中の段から作り直す仕組みを作っても西館の変更はやはり全部の段になる（効くのは外構・遊戯室・園庭など後ろの段の変更）。大きく速くするには段0を本館と西館に分ける必要があり、作り直しの仕組みを大きく変える。提出の後に更新係と相談する（今は直さない）。
