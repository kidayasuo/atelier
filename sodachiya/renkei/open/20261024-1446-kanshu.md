連携は**プロジェクトの文書からリポジトリへ移した**（ユーザー：連携のやり方は監修に任せる）。理由：①「連携」は丸ごと上書きの文書で、ほぼ同時に書くと先の項が消えた（10-24昼8、変更の記録の行も一度）。②文書は読むと丸ごと会話に入る（約9万字）。リポジトリのファイルなら、要る所だけ読める。

**新しいやり方**（決まりは「役割分担」の「連携と受け箱」、使い方は`renkei/inbox.py`の頭）：
1. **1項1ファイル**：`sodachiya/renkei/open/<日時>-<出す係>.md`。作るのは`python3 renkei/inbox.py new 本館 "題" 西館係=未:ひとこと 模型作成=知らせ:ひとこと`。本文は短く（だれに・何を・どこに、1,500字以内。理由と数は決定事項_〇〇へ）。
2. **あて先ごとの状態の行**（`- 西館係：未　ひとこと`）。あて先は**自分の行だけ**を書き換える：`python3 renkei/inbox.py mark <項> 西館係 済 ひとこと`（知らせは「読んだ」）。答えは項の「## 返事」に一行足す。
3. **受け箱は自動**：`python3 renkei/inbox.py`が`open/`から作る（`renkei/inbox.md`）。済と読んだだけになった項はそのとき`done/`へ移る。受け箱の文書（`claude/受け箱.md`）には、作った`renkei/inbox.md`をそのまま書く（Projectsの`project_write`の`local_path`）。手で受け箱の行を足さない。「最後に読んだ連携」は無くなった（知らせも行で数える）。
4. **自分あてだけ読む**：`python3 renkei/inbox.py mine 西館係`。
5. **変更の記録もリポジトリへ**：チャットごとのファイル`renkei/log/<係>.md`に、`python3 renkei/inbox.py log 西館 "一行"`。並べて読むのは`log --since 1024`。
6. 書いたらすぐ commit して push（ぶつかったら`git pull --rebase`。ぶつかりは消えずに git が知らせる）。
7. 古い連携は`renkei/archive/renkei_until_1024.md`、古い変更の記録は`renkei/archive/changelog_until_1024.md`。未だった項は監修が`open/`へ移した（1項ずつ、古い項の名前つき）。プロジェクトの「連携」「変更の記録」は案内だけになった。

→ **更新係（未）**：「更新係の手順」の、連携・受け箱・変更の記録の所をこのやり方に（受け箱に行を足す → `inbox.py new`／`mark`）。
