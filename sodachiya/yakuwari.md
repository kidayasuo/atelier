## 自動の作り直し（設計監修、10-27。ユーザー：伝令をなくす）
- 作り直しが読むもの（`data/`・`scripts/plan01・02・04.py`・`model/build/`のスクリプト・取り込み用ファイル`model/*_layers.3dm`・`archive/handoff_1018/`・ロゴ・`present/kadai_map.json`）が main に push されると、GitHub Actions（`.github/workflows/sodachiya_build.yml`）が約2分待って続けての push をまとめ、最新の main で `run_all.sh --publish` を走らせる。できたもの（3dm・図・面積表・`stages.md`）を `[3dm] 自動の作り直し（<commit>まで）` で push する。push からおよそ30分。走っている間の push は一つの待ちにまとまり、終わったらもう一回だけ走る。読むものが変わっていなければ走らない。
- 結果を使うときは pull する（作り直しが終わったかは `renkei/log/auto.md` の最後の行か、`git log -1 -- model/drawings/sodachiya_check.txt`）。
- 通ったら、更新係あての「作り直し：…」の未の項を自動で済にする。**作り直しのための項は出さない**（push で足りる）。模型・プレゼンへの「形が変わった」知らせは今までどおり出す。
- **止まったら**（`check:` の止める、または段のエラー）：できたものは push せず、前の作り直しから commit した係（commitの頭で決める）あてに連携の項「自動の作り直しが止まった」（設計監修には知らせ）を立てる。項にはエラーの最後の行と実行のページ。自分の直しが原因なら直して push すれば、自動でもう一度走る。作り直しの仕組みの誤りなら更新係か監修。
- 確かめたいときは今までどおり `bash model/build/run_all.sh`（`--publish`を付けない）。できたものは `/tmp/claude-0/out/preview/` に入り、リポジトリは変わらない。最後の `check:` の行で、止める（✗）・知らせる（!）が無いかを見る。
- データを変えたらどの段から作り直しが要るかは `model/build/stages.md`（段ごとに読むもの、自動）。

## 連携と受け箱（設計監修、10-24夕。ユーザー：連携のやり方は監修に任せる）
前の「連携」は一つの文書を丸ごと上書きしていたので、ほぼ同時に書くと先の項が消えた（10-24昼8、変更の記録の行も）。読むと約9万字が丸ごと会話に入った。そこで連携をリポジトリに移し、**書く人を分けた**。使い方の細部は`sodachiya/renkei/inbox.py`の頭。
- **連携の項は1項1ファイル**：`renkei/open/<日時>-<出す係>.md`。作る：`python3 renkei/inbox.py new <自分> "題" <あて先>=未:ひとこと <あて先>=知らせ:ひとこと`。本文は「だれに・何を・どこに（ファイル・commit）」だけ、1,500字以内。理由・経緯・測った数は自分の決定事項_〇〇に書き、項からは名前で指す。模型・プレゼンへの知らせは1行ずつ。本文を書き直すのは出した係だけ。
- **未を出したら、その場でユーザーに伝える**（10-27、ユーザー：更新係の行を見張らなくてよいように）：あて先に「未」のある項を作ったら、その返事の終わりに一行「〇〇に一言お願いします（題）」と書く（`inbox.py new`が書く一行を出す）。ユーザーはそれを見てあて先のチャットへ行く。知らせだけの項は伝えない。
- **状態はあて先ごとの一行**（`- 西館係：未　ひとこと`、行のあいだは空ける）。未＝依頼、知らせ＝読んでほしい。あて先は**自分の行だけ**を変える：`python3 renkei/inbox.py mark <項> <自分> 済 ひとこと`（知らせは「読んだ」）。答えは項の「## 返事」に一行足す。ユーザーに聞くことは、あて先「ユーザー」の未の行（答えを聞いたチャットが済にする）。
- **受け箱は自動**：`python3 renkei/inbox.py`が`open/`から作る（`renkei/inbox.md`）。済と読んだだけになった項はそのとき`done/`へ移る。作ったら受け箱の文書（`claude/受け箱.md`）を、その`renkei/inbox.md`で上書きする（project_writeの`local_path`）。手で受け箱の行を書かない（誰がいつ作っても同じになるので、上書きでずれない）。
- **ユーザーが一言だけで来たら**（「お願い」など、言葉は何でもよい。ユーザー10-24：「受け箱」はちょっと変だった）：それは受け箱の自分の行を片づける合図。pull → `python3 renkei/inbox.py mine <自分>`（自分あての項だけを読む）→ 片づける（判断の要るものはユーザーに聞く）→ `mark` → `python3 renkei/inbox.py` → commit・push → 受け箱の文書を上書き。
- **知らせは取りに行く**（10-27）：どのチャットも、作業の始め（ユーザーの話が何であっても、その日の最初の作業の前）に pull して `python3 renkei/inbox.py mine <自分>` を走らせる。出てきた知らせは、そのとき自動で「読んだ」になる（残したいときは `--keep`）。読んだ分は commit・push する。
- **変更の記録もリポジトリ**：チャットごとのファイル`renkei/log/<係>.md`に`python3 renkei/inbox.py log <自分> "一行"`（1件1〜2行、約150字以内：何を・ユーザーの一言・commit・項）。並べて読む：`log --since 1024`。
- 書いたらすぐcommitしてpush（commitの頭は担当）。pushが拒まれたら`git pull --rebase`。ぶつかったら消えずにgitが知らせるので、両方を残して直す。
- 古い連携（〜10-24夕）は`renkei/archive/renkei_until_1024.md`、古い変更の記録は`renkei/archive/changelog_until_1024.md`（要る所だけgrepで読む）。

## 文書の読み方（会話を軽くする、ユーザー 10-21 夜）
長い文書を丸ごと何度も読むと会話がすぐ圧縮されるので：
1. 始めに読むのは役割分担（`sodachiya/yakuwari.md`）・「決定事項」（共通）「受け箱」と、自分の担当の分冊だけ。連携は`inbox.py mine`で自分あての項だけ。ほかの分冊・`name.md`・アーカイブは、要るときに project_search（リポジトリならgrep）で探してから読む。
2. 書く直前の読み直しは、書く文書だけ。「最終更新」の行は最新の一行だけにし、履歴は変更の記録に書く（長くしない）。
3. 済んだ連携の項は`inbox.py`が自動で`done/`へ移す。
4. 決定事項は短く、**今の決まりだけ**を書く（覆された決まりは消す。前の決まりは変更の記録とgitに残る。「〜はやめた」の経緯は1行まで。数字と結論だけ残す）。
5. 作業の中でも：図の確認は縮めた画像（長辺 1600 px くらい）で。スクリプトやコマンドの長い出力は必要な所だけ（tail・grep）。大きなファイルは丸ごと読まず、要る所だけ読む。

## チャットが溢れたとき（乗り換えの手順）
- **どのチャットも、自分から乗り換えを勧める**（ユーザー、10-27）：チャットが長くなって新しくした方がよいと判断したら、返事の終わりに「そろそろ新しいスレッドにしましょう」と伝える。目安：会話が一度でも自動で要約（圧縮）された、前の話の細部を読み直さないと答えられなくなってきた、これから長い作業を始める前。伝えたら、ユーザーの返事を待たずに下の1（決定事項・変更の記録・引き継ぎを書いて push）を済ませておく。
1. 古いチャットで（まだ書けるうちに）：決定事項と変更の記録（`renkei/log/`）を更新し、リポジトリに push する。担当の表（`sodachiya/yakuwari.md`）に「→ 新しいチャットの名前に引き継ぐ」と書く。
2. 新しいチャットを同じプロジェクトの中で始め、最初にこう頼む：
   > 育ち舎の続きです。atelier リポジトリを接続して `sodachiya/` を使い、役割分担（`sodachiya/yakuwari.md`）・「決定事項」・「受け箱」を読んでください（連携は`renkei/inbox.py mine`で）。あなたの担当は〇〇（前のチャット「△△」の続き）です。役割分担の表を更新して push してから始めてください。
   （更新係は「更新係の手順」の最後の一文を貼る）
3. 新しいチャットが表の行を書き換える（名前・状態、`sodachiya/yakuwari.md` を pull してから直してすぐ push）。古いチャットの行は「終了 日付」にする。
